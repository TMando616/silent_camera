# 無音カメラ（Swift）仕様書 v1

Nov 21, 2026 · @まんどぅ

## 概要と決定事項

シャッター音が鳴らず、色味フィルター5種とズームだけを持つシンプルなiOSカメラを、SwiftUIで作る。顔の加工はしない。広告収入で給料以外の収入を得ることと、画風変換アプリ（Core ML）の前にSwiftとカメラ周りに慣れることが目的。

| 項目 | 決定内容 |
| --- | --- |
| 言語・UI | Swift / SwiftUI |
| 対応OS | iOS 17以上（仮） |
| 無音の方式 | 動画フレームを切り出して保存 |
| フィルター | 5種（オリジナル・モノクロ・セピア・暖色・寒色） |
| 追加機能 | ズームのみ |
| 収益化 | 広告（AdMob） |

## 無音の仕組み

撮影は`AVCapturePhotoOutput`ではなく、`AVCaptureVideoDataOutput`が流す映像フレームをシャッターを押した瞬間に1枚切り出して保存する。

- **なぜ**：日本で売られているiPhoneでは、写真撮影APIを使うとシャッター音がOS側で強制的に鳴り、アプリから消せない。映像フレームの取得には音が付かない。
- **メリット**：プレビュー用のフレームにそのままフィルターをかけて表示できるので、「見えている通りに撮れる」仕組みが簡単に作れる。
- **デメリット**：解像度は動画の上限（最近の機種で4K・約830万画素）になり、通常の写真（1200万画素前後）より少し落ちる。Deep Fusionなど写真向けの画像処理も効かない。
- **注意**：カメラはシミュレーターでは動かない。動作確認は実機のiPhoneで行う。

## 画面構成

v1は撮影画面の1画面だけ。保存した写真は「写真」アプリで見てもらう。上から順に次の持ち方。

1. **上部バー**：前後カメラ切り替えボタン
2. **プレビュー**（画面の大部分）：フィルター適用済みの映像。ピンチでズーム。左右スワイプでフィルター切り替え
3. **ズームボタン**：0.5x / 1x / 2x（機種にない倍率は非表示）
4. **フィルター名の帯**：選択中のフィルター名を横並びで表示、タップでも切り替え
5. **撮影バー**：左に直前に撮った写真のサムネイル、中央にシャッターボタン
6. **バナー広告**：画面最下部。シャッターボタンとは余白を取る

撮影時は音の代わりに、プレビューを一瞬暗くする演出と軽い振動で「撮れた」ことを伝える。

## フィルター・ズーム・保存の仕様

フィルターはすべてCore Imageの標準フィルターで作り、プレビューと保存で同じ処理を通す。強さなどの値は実機で見ながら調整する。

| フィルター | Core Image | 初期値の目安 |
| --- | --- | --- |
| オリジナル | なし | — |
| モノクロ | CIPhotoEffectMono | — |
| セピア | CISepiaTone | intensity 0.8 |
| 暖色 | CITemperatureAndTint | 黄色寄りに少しずらす |
| 寒色 | CITemperatureAndTint | 青寄りに少しずらす |

**ズーム**

- 使うカメラは「トリプル → デュアルワイド → 広角」の順に、端末にあるものを選ぶ。これらは複数レンズをまとめた仮想カメラで、`videoZoomFactor`を変えるだけでOSがレンズを自動で切り替えてくれる。
- 超広角を含む仮想カメラでは実際の倍率1.0が0.5xに当たる。画面上の表示は広角レンズを1xとして換算する。
- ピンチは表示上10xまで。ボタンは`ramp`で滑らかに切り替える。
- 前面カメラでは倍率ボタンを隠す。

**保存**

- 解像度は4K（3840×2160、16:9）、非対応機種は1920×1080。
- 撮影時の端末の向きに合わせて回転させ、前面カメラは左右反転して保存する。
- JPEGで保存。位置情報は付けない（権限が増えるため）。

## 広告と権限・審査

広告は画面最下部のアダプティブバナー1つだけにし、撮影の邪魔になるインタースティシャル（全画面広告）はv1では使わない。

**広告（AdMob）**

- Google Mobile Ads SDKをSwift Package Managerで入れる。
- 開発中は必ずテスト用の広告IDを使う。自分で本番広告をタップするとアカウント停止の原因になる。
- シャッターの押し間違いでタップされる配置はポリシー違反になりやすいので、余白を取る。
- トラッキング許可（ATT）のダイアログを初回起動時に1回出す。拒否されても広告は出る（単価は下がる）。

**Info.plistに必要な許可文言**

- `NSCameraUsageDescription`：カメラで撮影するため
- `NSPhotoLibraryAddUsageDescription`：撮った写真を保存するため（読み取り権限は要らない）
- `NSUserTrackingUsageDescription`：広告の最適化のため
- `GADApplicationIdentifier`：AdMobのアプリID

**公開までに必要なもの**

- Apple Developer Programへの登録（年額制）。一問一答アプリのiOS公開と共通で使える。
- プライバシーポリシーのURL（広告のSDKがデータを扱うため）。
- App Storeの「プライバシーの栄養成分ラベル」への記入（AdMobの分を申告）。
- 説明文では「静かな場所で食事やペットを撮る」など用途をはっきり書く。盗撮を連想させる表現は審査で弾かれやすい。

## 実装ステップ（Claude Code用）

各ステップの終わりに実機で動作確認してから次に進む。広告は最後に入れ、カメラ部分の不具合と混ざらないようにする。

1. **プロジェクト作成**：XcodeでSwiftUIアプリを作り、実機でHello Worldを起動。署名は個人チームでよい。
2. **カメラ表示**：`CameraService`（AVCaptureSession管理）を作り、権限リクエストとプレビュー表示まで。
3. **フレーム取得とフィルター**：`AVCaptureVideoDataOutput`でフレームを受け、`FilterEngine`でCore Imageを適用してMetal（MTKView）で描画。
4. **無音撮影と保存**：シャッターで最新フレームを取り、向きを補正してJPEG化、PhotoKitで保存。暗転演出と振動もここで。
5. **ズームとカメラ切り替え**：仮想カメラの選択、ピンチ、倍率ボタン、前後切り替え、タップでピント。
6. **UIの仕上げ**：フィルター名の帯、スワイプ切り替え、サムネイル表示。
7. **広告**：AdMob SDK、テストIDでのバナー表示、ATTダイアログ。
8. **公開準備**：アイコン、スクリーンショット、プライバシーポリシー、TestFlightでの配布確認、審査提出。

想定するファイル構成：`CameraService.swift` / `FilterEngine.swift` / `PhotoSaver.swift` / `CameraView.swift` / `PreviewView.swift`（MTKViewのラッパー）/ `BannerAdView.swift`
